# Benchmark consolidation and analysis

Raw measurements in `benchmark` remain the source of truth. This environment
reads them with SQLite.jl, uses DataFrames.jl for joins and aggregation, and
rebuilds `generated/analysis.sqlite`. It never changes the catalog database.
Raw Julia Profile artifacts remain under `bench/profiles/`; FlameGraphs constructs
their call trees. Only project ownership classification is custom logic.

## Workflow

From the repository root:

```sh
make -C bench help
make -C bench setup-analysis
make -C bench benchmark          # collect public API timings, when needed
make -C bench benchmark-papers   # collect paper workloads, when needed
make -C bench consolidate        # no workload execution
make -C bench inspect-analysis
make -C bench export-all         # CSV and Arrow
make -C bench export-core
make -C bench export-papers
make -C bench export-profiles    # sessions and component rows
make -C bench plots-runtime      # optional exploratory Plots.jl figure
make -C bench plots-approach
make -C bench plots-profiles
make -C bench test-analysis
make -C bench clean-analysis
```

`export` aliases `export-all`; `plots` invokes all exploratory plots. Neither
depends on benchmark execution or automatically consolidates: run `consolidate`
after collecting additional data. Exports and plots read the saved analysis DB.
No final thesis figures are selected or generated by benchmark execution.
The existing `quick`, `bench`, `full`, and legacy `crossings` remain available.
`crossings` uses its historical CSV contract, separate from this pipeline.

Override `database=PATH`, `profiles=DIR`, and `analysis_output=DIR` on analysis
targets. `BFA_CATALOG_PATH` supplies the default raw DB. `clean-analysis` deletes
only the default generated analysis DB, CSV, Arrow, and PNG files, preserving raw
measurements and profiles. Custom output directories are managed explicitly.

## Thin Julia API

```julia
include("bench/analysis/BenchAnalysis.jl")
using .BenchAnalysis, DataFrames

df = derive_metrics(load_benchmarks())
papers = load_paper_benchmarks()
core = load_core_benchmarks()
profiles = load_profile_summaries()       # from analysis.sqlite
components = load_profile_components()
joined = join_profiles(df, profiles)
group_by_approach(joined)
group_by_dimension(joined)
group_by_mode(joined)

# Filter a comparable run/case first; by explicitly chooses pooling strata.
selected = filter(:run_id => ==("chosen-run-id"), joined)
runtime_statistics(selected; by=[:paper_id, :algorithm, :approach, :mode, :n])
runtime_statistics(selected; by=[:paper_id, :n], metric=:known_coverage)
core_vs_paper_fractions(selected)

# Components are normalized: join their session identity with DataFrames.
details = leftjoin(components, select(profiles, :profile_id, :paper_id, :algorithm,
    :approach, :mode, :n); on=:profile_id, validate=(false, true))
combine(groupby(details, [:profile_id, :paper_id, :subsystem]), :samples => sum)

include("bench/analysis/plots.jl")        # loads Plots only when requested
p = plot_runtime_vs_dimension(selected)
```

Load a SQL slice with bound values using
`load_benchmarks(path; where="paper_id = ?", params=("Beierle_202107",))`.
SQLite extracts the needed provenance fields from `parameters_json`; large
payload/identity JSON stays in the source DB. `include_raw=true` retrieves it too,
at a potentially substantial memory cost. Every analysis row retains `id`,
`run_id`, and `repetition` for tracing it to the raw record.

Default grouping retains run, paper, case (`algorithm`), approach, mode, dimension,
case parameters, reference scope, source hash, CPU, Julia version/threads, and
seed. The three `group_by_*` helpers intentionally share these conservative
strata. Pass `by` to explicitly pool strata. Counts are observed repetitions;
do not treat adaptive repetition counts as equal weighting of papers or runs.
All-missing groups remain missing and singleton standard deviations are missing.

## Metrics and profiling semantics

`derive_metrics` adds `known_coverage`, `search_space_coverage`, and
`distinct_apns_per_second`. Missing or zero denominators produce `missing`.
Known coverage uses exact-LUT catalog identity and the persisted reference scope,
not CCZ/EA equivalence. `total_candidates` currently means all visited search
nodes in paper rows, whereas `candidates_processed` counts complete candidates.
Their ratio is therefore a visited-node completion ratio, **not necessarily a
fraction of the full mathematical search space**. The formula is retained under
the requested name; compare it only when case semantics support that meaning.

`profiles` has one row per distinct raw artifact (SHA-256 profile ID), its path,
case/provenance, sampling interval if known, counts, and estimated owner fractions.
`profile_components` has one row per profile/owner/subsystem/operation. Its
fractions share the session sample denominator. These are exclusive samples:
ancestor and descendant inclusive counts are never added together.

Ownership follows the nearest project frame: VBF and VBFCatalog are `core`,
paper sources are `paper`, and stacks without a project owner are `other`.
External callees inherit their project caller's ownership. VBF source directories
define subsystems; VBFCatalog is the `catalog` subsystem. The nearest project
function defines the operation. `runtime_fraction` aliases `other_fraction`.
It is unattributed runtime, not a measurement of all Julia internals. Compilation,
inlining, sampling delay, short calls and thread scheduling limit interpretation.
Zero-sample profiles yield missing fractions. A core_only mode is workload
metadata, not proof that its estimated core fraction must be 100%.

Joins require matching paper, case, approach, mode, dimension, case parameters,
source hash, Julia version/threads, CPU, and seed. Compatible sessions are pooled
by summing samples before dividing. This is sample weighting, not an average of
fractions or independent timing. The validated many-to-one join cannot multiply
benchmark repetitions. Estimated seconds multiply the joined fractions by the
unprofiled elapsed time. Profile evidence is repeated alongside timing rows;
never sum its sample counts over repetitions. Analyze independent profile evidence
through the normalized session/component tables.

Legacy saved profiles lack source/configuration provenance. Consolidation rebuilds
their subsystem summaries but marks them `joinable=false`; it does not guess a
timing match. Future `profile.jl` artifacts contain those identifiers. Strict source
matching can also leave profiles unmatched after code changes; this is deliberate.
Separate executions can differ in mutable/random workload state even with matching
configuration, so a joined estimate is explanatory evidence, not an exact split.

Only deserialize trusted local Julia artifacts. Julia Serialization preserves the
existing `Profile.retrieve()` data and frame dictionary; keep its Julia environment
with it. JSON summaries and optional SVGs are diagnostic exports. ProfileView,
FlameGraphs and ProfileSVG remain available; raw flame graphs are not the main
thesis visualization.

## Storage recommendation

| Representation | Best use | Trade-off |
| --- | --- | --- |
| Dynamic SQL/DataFrames | Exploration and inexpensive ratios | Always current; repeats computation |
| SQL views | Stable SQL-only projections | No duplicated rows; cannot reconstruct Julia profile trees |
| Derived SQLite tables | Reusable joins and normalized profile summaries | Fast repeated queries; must rebuild after raw data or analysis changes |
| CSV | Sharing and inspection | Portable text; loses types and explicit schema |
| Arrow | Typed analysis-ready interchange | Preserves nulls/types and supports efficient column access; binary |
| Parquet | Large cross-tool analytical datasets | Compressed columnar storage; another package and format to maintain |

Use a **separate disposable SQLite analysis DB plus CSV/Arrow exports**, as
implemented here. Dynamic DataFrames operations stay available. Do not add mutable
derived columns to the raw benchmark table. Normalized sessions and components
support multiple profiles per configuration and avoid repeating components in
every timing row. Raw artifacts remain authoritative for rebuilding profile
summaries; raw SQLite remains authoritative for benchmark measurements.

Consolidation atomically replaces its output tables in a SQLite transaction.
`provenance` records source DB path, snapshot row count/max ID, analysis version,
Julia version, analysis source/manifest hashes, and attribution rule; benchmark rows preserve original run/source
identifiers and profiles preserve artifact hashes. Keep the analysis sources and
resolved `Manifest.toml` with any published snapshot. The local manifest and
generated outputs are ignored; no generated result belongs in source control.

SQLite, JSON3, FlameGraphs and AbstractTrees reuse existing project packages.
DataFrames, CSV, Arrow and Plots live in this separate environment: their standard
table operations and exporters replace custom grouping, serializers, and plotting.
The existing timing harness has bespoke repetition/persistence semantics; this
post-processing change does not alter its timing protocol. BenchmarkTools is the
preferred package for future microbenchmark protocol work, which should be versioned
as a measurement change rather than mixed with historical rows silently.

Package references: [DataFrames joins](https://dataframes.juliadata.org/stable/man/joins/),
[SQLite Tables integration](https://juliadatabases.org/SQLite.jl/dev/),
[CSV export](https://csv.juliadata.org/latest/).
